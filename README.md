# Мои дела — одно ядро для Telegram, ВКонтакте и MAX

Простой личный задачник для России и русскоязычного СНГ. **Сразу три канала**, одинаковая логика и одна база YDB Serverless в России. Пока нет автоматического объединения учётных записей между разными мессенджерами: это необходимо делать только с подтверждением пользователя.

Интерфейс везде один: **➕ Добавить задачу · 📋 Мои задачи · 📊 Скачать Excel**.

Создание: **Работа / Личное → Что сделать? → Какой срок? → Когда напомнить? (➕ Ещё / ✅ Готово) → Приоритет**. Редактор: добавить информацию / изменить параметры / статус / удалить. Напоминания назначаются на конкретные даты; после «Сделано» отменяются. Excel содержит **строго два листа «Работа» и «Личное»**, с обычными фильтрами.

## Что уже написано

- `bot.py` — общая логика: задачник, редактирование, напоминания, Excel, без дублирования по платформам.
- `telegram_api.py`, `main.py` — Telegram Bot API и встроенный Telegram-триггер Yandex Functions.
- `messengers.py` — адаптеры VK (`messages.send`, кнопки, ответ на callback, XLSX через документы) и MAX (Bot API, кнопки, XLSX через uploads).
- `platform_events.py` — нормализация событий VK Callback API и MAX Webhook; игнорируются групповые чаты.
- `vk_main.py` и `max_main.py` — отдельные HTTP-входы платформ с проверкой подписей/секретов.
- `scheduler_main.py` — общий таймер раз в минуту: отправляет уведомление только в мессенджер, где создана задача.
- `storage.py` и `schema.py` — одна российская YDB; ключ владельца имеет вид `tg:ID`, `vk:ID`, `max:ID`. Чужие задачи не перемешиваются.
- `exporter.py` — простая XLSX-выгрузка; `assets/avatar-approved.png` — утверждённая аватарка.

## Что понадобится от владельца

1. **GitHub**: публичный пустой репозиторий `moi-dela-bot`. Никаких токенов в коде.
2. **Telegram**: бот через BotFather → `TELEGRAM_BOT_TOKEN`. Установить утверждённое фото.
3. **VK**: сообщество с включёнными сообщениями и Callback API; токен сообщества (`VK_COMMUNITY_TOKEN`), числовой `VK_GROUP_ID`, секрет Callback API (`VK_CALLBACK_SECRET`), строка подтверждения (`VK_CONFIRMATION_CODE`).
4. **MAX**: верифицировать профиль самозанятого через Госуслуги на https://business.max.ru, создать бота и пройти модерацию. После этого получить `MAX_BOT_TOKEN` и придумать `MAX_WEBHOOK_SECRET` для подписки.
5. **Yandex Cloud**: платёжный аккаунт, YDB Serverless в `ru-central1`, Cloud Functions, API Gateway/HTTPS для VK/MAX, сервисные аккаунты с минимальными правами. Бесплатные лимиты есть, но расходы при превышении возможны.

Секреты задаются **только в окружении функций / защищённом хранилище**, не публикуются в GitHub и не отправляются в переписку.

## Настройка Yandex Cloud

**Одна общая база:** создайте YDB Serverless, сохраните `YDB_ENDPOINT` и `YDB_DATABASE`, назначьте сервисному аккаунту права на таблицы. Создайте функцию `moi-dela` с Python 3.12+, `requirements.txt`, точкой входа `init_db.handler`, выполните её однократно — создадутся таблицы. Затем создайте четыре функции/версии из того же кода (один архив, разные entrypoints):

| Точка входа | Для чего | Как вызывается |
|---|---|---|
| `main.handler` | Telegram | Триггер Yandex Cloud типа **Telegram**, обновления `message`, `callback_query` |
| `vk_main.handler` | ВКонтакте | HTTPS-адрес API Gateway → функция, Callback API `message_new`, `message_event` |
| `max_main.handler` | MAX | HTTPS-адрес API Gateway → функция, Webhook `message_created`, `message_callback`, `bot_started` |
| `scheduler_main.handler` | Все три | Timer раз в минуту, **только один общий таймер** |

Функции VK и MAX должны получать объект HTTP-события `{headers,body}`. Путь маршрутизации (например `/vk`, `/max`) настраивается в API Gateway, а не определяется из текста входящего события. VK ждёт буквальный `ok` и отдельное подтверждение при первой проверке; MAX ждёт HTTP 200 и заголовок `X-Max-Bot-Api-Secret`. Webhook MAX должен использовать HTTPS и доверенный TLS-сертификат. Для исходящих запросов MAX согласно документации может понадобиться доверие к сертификату Минцифры. **Эту сетевую часть нужно проверить после получения токенов.**

### Переменные окружения

```text
YDB_ENDPOINT=grpcs://ydb.serverless.yandexcloud.net:2135
YDB_DATABASE=/ru-central1/...   # путь базы YDB
BOT_TIMEZONE=Europe/Moscow
TELEGRAM_BOT_TOKEN=...           # только для TG и общего таймера
VK_COMMUNITY_TOKEN=...          # только для VK и общего таймера
VK_GROUP_ID=...                 # для VK
VK_CALLBACK_SECRET=...          # для VK
VK_CONFIRMATION_CODE=...        # для VK
MAX_BOT_TOKEN=...               # для MAX и общего таймера
MAX_WEBHOOK_SECRET=...          # для MAX
```

- У входных функций достаточно токена своей платформы и общих параметров YDB.
- **Общий таймер** должен иметь токены всех трёх платформ, чтобы отправлять уведомления по назначению.
- `ALLOWED_USER_ID` — необязательный ограничитель тестовой версии на **один числовой ID платформы**. Для нескольких тестировщиков отключите и используйте отдельные ограничения на уровне доступа; не публикуйте открытый тестовый бот без готовности к общему доступу.
- Самозанятый может создать до двух MAX-ботов, но фактическая доступность зависит от верификации и модерации.

## Тестирование

```bash
python -m pip install -r requirements.txt
python -m pip install pytest
python -m pytest -q
```

Тесты проверяют общий сценарий, Excel, подписи вебхуков, нормализацию VK/MAX, изоляцию аккаунтов с одинаковыми числовыми ID и отправку уведомлений в свой мессенджер — **без внешних сетевых вызовов**.

## Ограничения текущей реализации

- Это **готовая кодовая заготовка**, но не развернутый публичный сервис. Настоящие VK/MAX callback и отправка XLSX требуют интеграционных испытаний с действующими аккаунтами; их ещё не было.
- Для Telegram, VK и MAX нужны отдельные регистрации ботов, права доступа и токены.
- Пользователь, впервые написавший в Telegram, не увидит свои задачи в VK автоматически. Учётные записи независимы, пока не появится безопасная добровольная привязка.
- Дедупликация повторных событий и атомарная отправка уведомлений в конкурентных условиях требуют дополнительных тестов перед массовым запуском. Для личного пилота проверяем под реальным расписанием.
- Для MAX новый домен API: `platform-api2.max.ru` (не старый `platform-api.max.ru`), требования MAX к сертификатам следует учесть в облаке.
